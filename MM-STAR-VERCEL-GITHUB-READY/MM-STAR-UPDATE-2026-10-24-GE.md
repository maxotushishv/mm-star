# MM STAR — 24 ოქტომბრის განახლება

## 1. ფოტოების ატვირთვის შეცდომა
`VERCEL_BLOB_NOT_CONFIGURED` ნიშნავს, რომ **Vercel-ის Production გარემოში** `BLOB_READ_WRITE_TOKEN` არ არის ხელმისაწვდომი. ეს არ არის პროდუქტის ან ფოტოს პრობლემა.

1. Vercel → MM STAR პროექტი → Storage → Create → Blob.
2. Blob-ის შექმნისას მიაბით იმავე პროექტს; თუ საცავი უკვე გაქვთ, გამოიყენეთ Connect Project.
3. Settings → Environment Variables-ში გადაამოწმეთ `BLOB_READ_WRITE_TOKEN` (საიდუმლო მნიშვნელობა არსად გააზიაროთ).
4. დარწმუნდით, რომ მონიშნულია **Production** (საჭიროების შემთხვევაში Preview-ც).
5. Deployments → Redeploy. შემდეგ ატვირთეთ ერთი JPEG/PNG სატესტოდ.

**შენიშვნა:** თუ Vercel Blob-ის შექმნა თქვენს ანგარიშზე შეზღუდულია ან გადახდას ითხოვს, მხოლოდ ამ ZIP-ის ატვირთვით პრობლემა ვერ მოგვარდება. საჭირო იქნება სხვა საცავი და კოდის შესაბამისი გადაკეთება.

## 2. FINA-დან დილერის მოძებნა
ადმინპანელი → დილერები → დამატება → საიდენტიფიკაციო კოდი → **FINA-ში ძებნა**.

სერვერი იყენებს დოკუმენტირებულ GET `/api/operation/getCustomersByCode/{code}` მეთოდს და მხოლოდ კითხულობს მონაცემებს. შეივსება სახელი, მისამართი, ტელეფონი და ელფოსტა, თუ FINA-ში არის. სამართლებრივი ფორმა FINA-ის პასუხში **არ არის დაზუსტებული**: `is_company` მხოლოდ ფიზიკურ/იურიდიულ პირს განასხვავებს, ამიტომ შპს/ინდმეწარმეს თქვენ ირჩევთ. კატეგორიებს, მომხმარებლის სახელს და პაროლსაც თქვენ ქმნით. მონაცემების შესანახად კვლავ უნდა დააჭიროთ **შენახვა**.

თუ FINA-ს კლიენტების ბაზაში კოდი არ მოიძებნა, ფორმა არ წაიშლება და ველები შეგიძლიათ ხელით შეავსოთ. საიტის კოდი FINA-ში არაფერს ამატებს.

## 3. შეცდომით მონიშნული შეკვეთა
ადმინპანელი → შეკვეთები (ან დილერის შეკვეთები) → „FINA-ში გატარებულად მონიშნულია“ → **მონიშვნის გაუქმება**. შემდეგ შეგიძლიათ შეკვეთა წაშალოთ. გაუქმებისას FINA-სთვის გამოყოფილი ადგილობრივი რეზერვი აღდგება; წაშლისას კი ადგილობრივი მარაგი უკან ბრუნდება. გამოიყენეთ მხოლოდ მაშინ, თუ შეკვეთა **რეალურად არ გაგიტარებიათ FINA-ში**.

პროდუქტების წაშლის ღილაკი ცალკე მუშაობს და FINA-ს მონაცემებს არ შლის. FINA-ში რეალურად გატარებული ოპერაციის გაუქმება ამ ფუნქციით არ ხდება.

## 4. სხვა
FINA-ის მარაგების სინქრონიზაცია ისევ ILHAMA №9-ზეა. ორ საწყობს არ ვაერთიანებთ. GitHub Actions-ის 5-წუთიანი გაშვების კონფიგურაცია შენარჩუნებულია.
