# MM STAR — განახლება (22.10.2026)

## დამატებულია
- მომხმარებლის მაღაზიასა და პროდუქტის დეტალებში მარაგის **რაოდენობა** აღარ ჩანს; მარაგის არსებობა კვლავ ამოწმებს კალათასა და შეკვეთას.
- მთავარ გვერდზე გამოყოფილია „სააქციო პროდუქტები“ (მხოლოდ პროდუქტები რეალური ფასდაკლებით), ძველი და ახალი ფასებით; „ყველა აქციის ნახვა“ აჩვენებს აქციებს.
- ადმინში პროდუქტების ძებნა სახელით/კოდით, კატეგორიის, ქვეკატეგორიის, აქციისა და მარაგის ფილტრები.
- ყოველ 5 წუთში ავტომატური **მხოლოდ ნაშთების** FINA სინქრონიზაციის უსაფრთხო API endpoint `/api/cron/fina-sync`. ერთდროული გაშვება იზღუდება Firestore lock-ით; შეცდომები იწერება `settings/fina-last-sync` დოკუმენტში.
- ერთი საწყობი რჩება: `FINA_STORE_ID=9` (ILHAMA). ორი საწყობის გაერთიანება **არ დამატებულა**.

## Vercel-ის აუცილებელი პარამეტრები
1. `FINA_ENABLED=true`, `FINA_STORE_ID=9`, `FINA_AUTO_SYNC=true`.
2. `CRON_SECRET` — შექმენით გრძელი შემთხვევითი საიდუმლო (Vercel ავტომატურად გადასცემს Bearer header-ში). **არ ჩაწეროთ საიტზე/კოდში.**
3. `FINA_LOGIN`, `FINA_PASSWORD`, `FINA_API_URL` — სერვერის საიდუმლო გარემოს ცვლადები. FINA API-სთან გამოიყენეთ HTTPS ან დაცული ტუნელი; HTTP-ით პაროლი დაუცველად გადაიცემა.
4. GitHub-ზე ატვირთვის შემდეგ Vercel-ის ახალი Production deployment გაუშვით.
5. `vercel.json` შეიცავს `*/5 * * * *` Cron schedule-ს. **Vercel Hobby გეგმა 5-წუთიან Cron-ს შესაძლოა არ უშვებდეს** — ასეთ შემთხვევაში საჭიროა შესაბამისი ფასიანი გეგმა ან გარე scheduler, რომელიც GET `/api/cron/fina-sync`-ს `Authorization: Bearer <CRON_SECRET>`-ით გამოიძახებს.
6. `FINA_SYNC_PRICES` ავტომატურ სინქრონიზაციაზე გავლენას ვერ ახდენს: Cron იძულებით იყენებს `syncPrices:false` და `fields:'stock'`. ხელით „ყველაფრის“ რეჟიმი კვლავ ცალკე მოქმედებს.
