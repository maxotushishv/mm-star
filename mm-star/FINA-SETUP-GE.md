# MM STAR ↔ FINA Web API 8.0 — ჩართვის ინსტრუქცია

## მიმდინარე მდგომარეობა

კოდი ინტეგრირებულია, მაგრამ **რეალური FINA API-თან კავშირი ჯერ არ დადასტურებულა**. მომხმარებელმა მოგვაწოდა Swagger მისამართი `http://188.129.172.6:8011/swagger/index.html`; ეს მისამართი ჩვენი სამუშაო გარემოდან ვერ გაიხსნა. სერვერის ქსელი, firewall, Swagger schema და ავტორიზაცია რეალურ გარემოში უნდა გადამოწმდეს. პროგრამა არსებულ პროდუქტებს არ ცვლის, სანამ FINA_ENABLED არ ჩაირთვება და სინქრონიზაცია არ შესრულდება.

## მოთხოვნილი ქცევა

- საიტის პროდუქტის `code` ემთხვევა FINA `getProducts`-ის `code`-ს **ზუსტად**, საწყისი ნულების ჩათვლით. დამთხვევისას მარაგი განახლდება FINA-ს არჩეული საწყობის `getProductsRestByStore/{store}`-ით. პროდუქტები არ იშლება, არ იქმნება, ფოტოები/კატეგორიები უცვლელია.
- ადმინისტრატორში პროდუქტის დამატებისას `FINA-დან მოძებნა` შეავსებს: **დასახელება = FINA name**, **აღწერა = იგივე FINA name**, **ჩვეულებრივი ფასი = `საცალო`**, **დილერის ფასი = `მცირე საბითუმო`**, **რაოდენობა = FINA-ს არჩეული საწყობის ნაშთი**. შენახვამდე ყველა ველი ხელით რედაქტირებადია.
- `getPriceTypes`-ით ფასის ტიპები ავტომატურად იძებნება სახელებით `საცალო` და `მცირე საბითუმო`; შესაძლებელია ID-ების ხელით მითითებაც. ფასები ლარში უნდა იყოს.
- ადმინის „ინტეგრაციები“ გვერდზე არის API კავშირის/საწყობების/ფასების შემოწმება, dry-run და ხელით სინქრონიზაცია.
- Netlify Scheduled Function მუშაობს **ყოველ 10 წუთში**, როცა `FINA_AUTO_SYNC=true`. ავტომატურად ცვლის მხოლოდ ნაშთს (ფასებს მხოლოდ `FINA_SYNC_PRICES=true`-ზე). ეს არ არის მყისიერი webhook; FINA-ს ცვლილებები ჩანს მომდევნო წარმატებულ სინქრონიზაციაზე.
- **FINA-ში არ იგზავნება არაფერი**: არც გაყიდვა, არც შეკვეთა, არც ინვოისი, არც პროდუქტის ცვლილება. ავტორიზაციის გარდა გამოიყენება მხოლოდ GET მეთოდები.

## საიტის შეკვეთები და ნაშთების დაცვა

FINA-ში ჯერ არ გადის საიტის შეკვეთები. ამიტომ როცა `FINA_ENABLED=true`, ახალი საიტის შეკვეთა ქმნის ადგილობრივ რეზერვს (`finaPendingQty`) და ამცირებს საიტის `stock`-ს. FINA-დან მომდევნო სინქრონიზაცია ითვლის `stock = max(0, FINA rest - finaPendingQty)`; Firestore transaction იცავს პარალელურ გაყიდვებთან კონფლიქტისგან. ეს მუშაობს როგორც მომხმარებლების, ისე დილერების შეკვეთებზე და Keepz-ის გადახდის დაჯავშნაზე.

როცა შეკვეთა **ხელით გაატარე FINA-ში**, ადმინისტრატორში შესაბამის შეკვეთაზე დააჭირე „✓ FINA-ში გატარებულია“. ამ დროს ადგილობრივი რეზერვი მოიხსნება, მაგრამ **FINA-ში არაფერი გაიგზავნება**. შემდეგი სინქრონიზაცია აიღებს FINA-ს ახალ ნაშთს. მონიშვნა გააკეთე მხოლოდ რეალური გატარების შემდეგ; FINA-ში გატარებულ შეკვეთას საიტიდან პირდაპირ ვერ წაშლი, რომ მარაგი შემთხვევით არ გაიზარდოს.

**მნიშვნელოვანი გადასვლის შეზღუდვა:** ძველ შეკვეთებს, რომლებიც FINA_ENABLED-ის ჩართვამდე შეიქმნა, `finaPendingQty` არ აქვთ. პირველ სინქრონიზაციამდე შეადარე ღია ძველი შეკვეთები და FINA-ს ნაშთი, ან გაატარე ისინი FINA-ში. ძველი ღია შეკვეთების ავტომატური რეზერვაცია არ ხდება. სტატუსის `CANCELLED` შეცვლა ძველი POS-ის მსგავსად მარაგს ავტომატურად არ აბრუნებს; ასეთი შეკვეთების მარაგი ცალკე უნდა შეამოწმო. სჯობს პირველი გაშვება არ გააკეთო გაყიდვების პიკის დროს.

## Netlify → Site configuration → Environment variables

| ცვლადი | მნიშვნელობა |
|---|---|
| `FINA_ENABLED` | ჯერ `false`, რეალური კავშირის შემოწმების შემდეგ `true` |
| `FINA_API_URL` | `http://188.129.172.6:8011` **მხოლოდ იმ შემთხვევაში, თუ რეალურად ხელმისაწვდომია**; უმჯობესია HTTPS პროქსი/VPN bridge |
| `FINA_LOGIN` | FINA API-ს მომხმარებელი (მხოლოდ Netlify secret-ში) |
| `FINA_PASSWORD` | FINA API-ს პაროლი (მხოლოდ Netlify secret-ში) |
| `FINA_STORE_ID` | FINA-ს საწყობის ID; ნახე ადმინში „კავშირის შემოწმება“ |
| `FINA_RETAIL_PRICE_ID` | არასავალდებულო; ავტომატურად მოიძებნება `საცალო` |
| `FINA_WHOLESALE_PRICE_ID` | არასავალდებულო; ავტომატურად მოიძებნება `მცირე საბითუმო` |
| `FINA_AUTO_SYNC` | `false` პირველ შემოწმებამდე; მერე `true` |
| `FINA_SYNC_PRICES` | `false` — ფონურად მხოლოდ ნაშთები; თუ `true`, ფასებიც განახლდება |
| `FINA_TIMEOUT_MS` | `12000` (არასავალდებულო) |

**არ ჩაწერო პაროლი HTML-ში, GitHub-ში ან ამ ZIP-ში.** საჯარო HTTP-ით ავტორიზაციისას ლოგინი და პაროლი დაუშიფრავად გადაიცემა; გამოიყენე უსაფრთხო HTTPS reverse proxy ან დაცული bridge. Swagger UI-ის არსებობა არ ადასტურებს, რომ Netlify-დან API ხელმისაწვდომია.

## ჩართვის რიგი

1. დააყენე ახალი ZIP-ის საიტი Netlify-ზე (თავდაპირველად FINA_ENABLED=false).
2. Netlify-ის secret variables-ში შეიყვანე API მისამართი, მომხმარებელი და პაროლი. დროებით FINA_ENABLED=true, FINA_AUTO_SYNC=false. Redeploy.
3. ადმინში „ინტეგრაციები“ → „კავშირის შემოწმება“. აირჩიე სწორი საწყობის ID; საჭიროებისას შეცვალე Netlify-ში და Redeploy.
4. ჯერ **წინასწარი შემოწმება**; გადაამოწმე კოდების დამთხვევა და ნაშთები, ძველი შეკვეთები და დუბლიკატები.
5. ხელით გაუშვი „მხოლოდ რაოდენობები“ და ცალკე პროდუქტის კოდით მოძებნა.
6. მხოლოდ წარმატებული ტესტის შემდეგ ჩართე FINA_AUTO_SYNC=true და Redeploy.

## API მეთოდები

- `POST api/authentication/authenticate` — 36-საათიანი token.
- `GET api/operation/getProducts` — კოდი და დასახელება.
- `GET api/operation/getProductPrices` — ფასები.
- `GET api/operation/getPriceTypes` — ფასის ტიპების ID/სახელები.
- `GET api/operation/getProductsRestByStore/{store}` — ნაშთები.
- `GET api/operation/getStores` — საწყობები.

ტესტები: `node --test tests/fina.test.mjs`.
